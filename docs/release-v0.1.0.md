## PV_Dictionary v0.1.0 — 帳號管理與授權管理

使用者指示：「先把帳號管理做完，兩件一起上線」（兩件＝帳號管理＋連上網）。
這一版把**介面上的帳號管理與授權管理**做完；連上網（Supabase adapter + Vercel）緊接在下一版，
因為那一步需要你自己把 `service_role` key 填進 `.env`（我不會、也不該經由對話拿）。

### 新增的畫面

管理員（admin 以上）登入 → 右上角「✏️ 管理」→ 管理區多了兩個面板：

**👥 帳號管理**
- 表格：帳號、顯示名稱、角色（比自己低的角色可以直接在下拉選單改）、狀態、最後登入、操作
- 「➕ 新增帳號」：帳號／顯示名稱／密碼／角色（可選的角色只有你能指派的，不含比自己高的）
- 每一列可以：改顯示名稱、重設密碼（行內輸入，成功就收起來）、停用／啟用、**刪除（要按兩次）**
- 停用後那個帳號就登不進來；刪除會連他的授權一起清掉（不會留下孤兒授權）

**🔑 授權管理**
- 授權「某個人」編輯「整本書」或「某一個單元」，並可勾選「也可以發佈」
- 清單會顯示授權對象、範圍（書名／Unit N）、權限、誰授權的；移除也要按兩次
- 老師與管理員本來就能編輯全部，這裡是給「科代表／學生／被指定的老師」加範圍

### 權限規則（真的有擋，不是只藏按鈕）

| 規則 | 結果 |
|---|---|
| 只有 admin 以上看得到帳號／授權管理 | 老師登入看不到，直接打 `/api/admin/users` 也是 403 |
| 不能管理自己 | 改自己、刪自己 → 403／`CANNOT_DELETE_SELF` |
| admin 不能動網站管理員 | 403 |
| 網站管理員之間可以互相管理（不能動自己） | 可以建立同級、也能移除多餘的同級 |
| 系統至少留一位網站管理員 | 動到最後一位 → `LAST_WEB_MANAGER` |
| 授權重複 | 409 `GRANT_EXISTS`（不是靜默新增第二筆） |
| 新的稽核動作 | `USER_DELETE`／`GRANT_CREATE`／`GRANT_DELETE`，英中都有翻譯 |

> 這一版改了一條規則：**網站管理員之間可以互相管理**（原本誰都不能動 web_manager，
> 結果第二個 site manager 建立後就永遠改不了、也刪不掉）。安全底線由「不能動自己 +
> 至少留一位」守著。`tests/roles.test.js` 已同步這條規格。

### 測試（實跑）

| 項目 | 指令 | 結果 |
|---|---|---|
| 語法 + 模組載入 | `npm run check:syntax` | 31/31 通過 |
| 單元／API／i18n | `npm test` | **49 通過 / 0 失敗**（新增 4 項帳號與授權的 API 測試） |
| 真 Chrome 驗收 | `npm run check:browser` | **四支檢查全綠**（新增 `users-check.js`） |

新的 `users-check.js` 是**真的在畫面上操作**：登入 → 開管理 → 建帳號 → 用新密碼真的登入成功 →
行內改角色（驗資料庫）→ 重設密碼（驗新密碼可用、舊密碼失效）→ 停用（驗登不進來）→
刪除（先按一次確認帳號還在，再按一次才消失）→ 授權單元（驗被授權的人從 403 變成可以新增）→
移除授權（又回到 403）→ 稽核紀錄看得到新動作 → 切中文全部跟著翻譯 → 402px 不溢出、
表格自己在框內捲動、無 CSP 違規、無前端例外、不下載、不寫截圖。

### 怎麼試

```bash
node server.js            # http://localhost:3000
grep SEED_ .env           # manager / webmanager / teacher / classrep 的密碼
```

用 `manager` 登入 → 右上「✏️ 管理」→ 捲到「👥 帳號管理」。
（`npm run seed -- --reset` 會把資料清空、只留 4 個種子帳號。）
