### v0.0.2 實作結果（2026-10-07，使用者實測後回報）

使用者實測回報三件事，這一版全部處理：

1. **「沒有辦法關閉錄音」「開始頁面不是學生」是同一個 CSS bug**：`.modal { display: flex }`、`.panel { display: flex }`
   這些作者樣式會蓋掉瀏覽器對 `[hidden]` 的 `display: none`，所以**設了 hidden 的登入視窗、錄音視窗與整個管理面板
   在開站時就蓋在頁面上，按關閉也關不掉**（程式其實把 hidden 設對了）。
   修法：`app.css` 全域加 `[hidden] { display: none !important; }`（唯一守門，註解寫明不要移除）。
   教訓：**驗「有沒有顯示」一定要看算出來的樣式（`getComputedStyle`），只看 `hidden` 屬性是騙自己**。
2. **角色 `web_owner` 改名為 `web_manager`**（`admin` 不變，標籤「網站管理員」）；`normalizeRole()` 保留
   `web_owner → web_manager` 的相容對照，免得舊資料的帳號被降成訪客。種子帳號改為 `webmanager`。
3. **預設不預填任何生字**：`npm run seed` 只建立帳號，內容全空、由使用者自己加入；要示範教材才加 `--with-sample`。
   同時補齊「空白起步」的可用性：起始畫面直接寫出建立順序、開站不再有彈窗蓋住頁面、
   「✏️ 管理」移到右上角（沒有書本時也進得去，否則第一次使用永遠建立不了第一本書）、
   沒有書本／單元時按鈕直接停用並說明原因。

測試：`npm test` **36 通過 / 0 失敗**；`npm run check:browser` **69 通過 / 0 失敗**
（新增 `empty-start-check.js` 30 項：空白資料下的學生視角、彈窗真的開得起來也關得掉、管理員建立第一本書與單元的完整流程）。

## 一、專案目標

給英文老師與學生使用的線上生字字典：

1. 學生：點書本 → 點單元 → 看該單元生字表 → 點生字即可聽讀音（免登入）。
2. 每個生字包含：生字、讀音（IPA 音標）、詞性、中文解釋、英文解釋（Demo 另含英文例句欄位）。
3. 生字由老師／科代表／管理員／被授權的人加入；科代表的新增要老師核准。
4. 角色階梯 + 單元級授權，比照 `competition-manager` 已驗證的做法。

## 二、技術架構（決定）

| 項目 | 決定 | 理由 |
|---|---|---|
| 後端 | Node.js + Express 5（CommonJS） | 沿用 competition-manager，已驗證 |
| 資料層 | `lib/store/` 介面 + 兩個 adapter：`json`（Demo 預設）、`supabase`（正式） | 使用者選 JSON → 開機即用；schema 契約同一份，切換只換 `DATA_BACKEND` 環境變數 |
| 前端 | 原生 HTML/CSS/JS（無框架、無 build step） | CSP 嚴格、無 unsafe-inline |
| 驗證 | JWT 存 **HttpOnly cookie**，前端不碰 token | competition-manager v3.5.0 起的作法 |
| 密碼 | scrypt（`lib/passwords.js` 直接複用） | 已有實作與測試 |
| 部署 | Vercel（`api/index.js` = `module.exports = require('../server')`；vercel.json `rewrites: /(.*) → /api/index.js`） | 沿用 competition-manager 形狀；**不要**用 `[[...route]]` 檔案路由（只吃一段路徑） |
| 音檔 | base64 存 store + 自家同源端點 `GET /api/audio/:id` | 沿用海報／規程 PDF 做法：**CSP 不必放寬、不需外部物件儲存** |
| 版本管理 | GitHub + 逐版發佈（比照 competition-manager：vX.Y.Z + annotated tag + Release） | 使用者慣例 |

**可直接複用（從 competition-manager 搬，不重寫）**：
`lib/passwords.js`、`tests/support/fake-supabase.js`（切 Supabase 後用）、`tests/browser/lib/cdp.js`
（含「不寫截圖」「攔下載」機制）、`public/js/csv.js`、`vercel.json` headers 區塊、`scripts/lib/cm-api.js`。

### JSON adapter 的注意事項（誠實揭露）

- 資料檔 `data/store.json`（`.gitignore` 排除），寫入用「讀-改-寫 + 單一寫入佇列」；**Demo 為單機單一實例，
  不做多實例並發保護**（會寫在 README，上線前切 Supabase）。
- 老師錄音的 base64 直接存在 JSON 內（Demo 資料量小）；`data/` 需要時可整包複製備份。
- **schema 契約以 `migrations/*.sql` 為唯一真實來源**，JSON adapter 只是「照同一組欄位存」，
  切 Supabase 時欄位名不會出意外。

## 四、資料模型

> 原則：**前端永不直連資料庫**。切到 Supabase 時伺服器用 `service_role` key，所有表
> `enable row level security` 且**不加 policy**、`revoke all from anon, authenticated`
> （competition-manager 2026-09-25 後的做法）。migration 一律 idempotent，由使用者手動執行。
> **表名一律 `dict_` 前綴**（避免與既有專案衝突，也方便日後共存或整批搬移）。

| 表 | 欄位 |
|---|---|
| `dict_books` | id, code(unique), name, grade, publisher, sort_order, is_published, created_at, updated_at |
| `dict_units` | id, book_id→books, unit_no, title, sort_order, is_published, created_at, updated_at；`unique (book_id, unit_no)` |
| `dict_entries` | id, unit_id→units, headword, headword_norm, ipa_us, ipa_uk, part_of_speech, zh_meaning, en_definition, example_en, example_zh, status(`published`/`pending`/`draft`/`rejected`), review_note, reviewed_by, reviewed_at, sort_order, created_by, updated_by, created_at, updated_at；`unique (unit_id, headword_norm)` |
| `dict_audio` | id, entry_id→entries, source(`teacher`/`tts`), accent(`en-US`/`en-GB`), mime, bytes, duration_ms, data(base64 ≤1MB), uploaded_by, created_at |
| `dict_users` | id, username(unique), display_name, password_hash, role, is_active, last_login_at, created_at, updated_at |
| `dict_grants` | id, user_id, book_id(可空), unit_id(可空), can_edit, can_publish, granted_by, created_at ←「授權的人」 |
| `dict_audit_logs` | id, user_id, action, target_id, details, created_at |

`headword_norm = lower(btrim(headword))` → 同一單元不重複生字。
索引：`dict_units(book_id)`、`dict_entries(unit_id, sort_order)`、`dict_audio(entry_id)`、`dict_audit_logs(created_at desc)`。

## 五、權限模型

### 角色階梯（唯一權威在 `lib/roles.js`）

```
guest(訪客) < student(學生) < class_rep(科代表) < teacher(老師) < admin(管理員) < web_manager(網站管理員)
```

函式：`levelOf(role)`、`atLeast(actor, role)`、`canManageUser(actor, target)`（嚴格高於目標、不能是自己）、
`canEditUnit(actor, unit)`（老師以上，或有 `dict_grants` 且 `can_edit`）、
`canPublish(actor, unit)`（老師以上，或有 grant 且 `can_publish`）、
`needsReview(actor, unit)`（科代表或只有 `can_edit` 無 `can_publish` 的 grant → 寫入 `status='pending'`）。

### 權限矩陣

| 動作 | guest | student | class_rep | teacher | admin | web_manager |
|---|---|---|---|---|---|---|
| 瀏覽書本／單元／生字、聽讀音、搜尋（免登入） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 新增／編輯生字（被授權的單元） | ✗ | ✗ | ✓（待審核） | ✓ | ✓ | ✓ |
| 核准／退回待審核生字 | ✗ | ✗ | ✗ | ✓ | ✓ | ✓ |
| 上傳老師錄音 | ✗ | ✗ | ✗ | ✓ | ✓ | ✓ |
| 新增／編輯書本與單元 | ✗ | ✗ | ✗ | ✓ | ✓ | ✓ |
| 發佈／下架單元 | ✗ | ✗ | ✗ | ✓ | ✓ | ✓ |
| 批次匯入生字 | ✗ | ✗ | ✓（待審核） | ✓ | ✓ | ✓ |
| 使用者管理（建立帳號、改角色、停用） | ✗ | ✗ | ✗ | ✗ | ✓ | ✓ |
| 授權管理（指派 `dict_grants`） | ✗ | ✗ | ✗ | ✗ | ✓ | ✓ |
| 稽核日誌 | ✗ | ✗ | ✗ | ✗ | ✓ | ✓ |

- **後端一律重新驗證**（前端隱藏按鈕只是體驗；驗證時要用「開發者工具硬塞」的方式確認後端真的擋）。
- **401 = 未認證、403 = 已認證但權限不足**，前端處理必須分開（competition-manager 教訓：混用會「選錯角色就被登出」）。
- 學生檢視端只回 `status='published'` 的生字；科代表／老師在管理檢視看得到自己的待審核項目。

## 六、讀音（發音）設計

| 方案 | 做法 | 成本 | 採用 |
|---|---|---|---|
| A. 瀏覽器 TTS | 前端 `speechSynthesis`，可選 `en-US` / `en-GB` | 0 元、零檔案 | ✅ **預設，開箱即用** |
| B. 老師錄音 | 選檔上傳或 `MediaRecorder` 錄音 → 存 `dict_audio` → 同源端點播放 | 老師人力 | ✅ **可個別覆蓋 TTS** |
| C. 伺服器端預生成 MP3 | 外部 TTS（Google／OpenAI）生成 mp3 存 DB | API key + 費用 | ⬜ v0.3.0 |

播放優先序：**有老師錄音 → 播錄音（顯示 👩🏫 徽章）；沒有 → 瀏覽器 TTS**。UI 同一顆 🔊，使用者不必理解差異。

誠實限制（要寫在介面說明）：TTS 聲音取決於裝置與瀏覽器（iOS／Android／桌機不同）；iOS Safari 必須在
使用者手勢中播放（點 🔊 正是手勢）；瀏覽器不支援 TTS 時按鈕停用並提示「請改用老師錄音」。

## 七、API 清單（`/api` 前綴，全部經 Express）

**公開（免登入）**
- `GET /api/books` → 書本清單（含各書單元數）
- `GET /api/books/:id/units` → 單元清單（含生字數）
- `GET /api/units/:id` → 單元 + 已發佈生字（含 `has_audio`、`audio_id`，**不含 base64**）
- `GET /api/audio/:id` → 音檔本體（`Cache-Control: public, max-age=31536000, immutable`）

**認證**
- `POST /api/auth/login`（設 HttpOnly cookie；IP 10 次/15 分鐘鎖定）、`POST /api/auth/logout`、`GET /api/auth/me`
- `POST /api/admin/users`（admin 以上建立帳號；Demo 由管理員建立老師／科代表帳號）

**編輯**
- `POST /api/units/:id/entries`、`PATCH /api/entries/:id`、`DELETE /api/entries/:id`
- `POST /api/entries/:id/review`（`{action:'approve'|'reject', note}`；teacher 以上）
- `POST /api/units/:id/entries/import` → 每行 `生字⇥IPA⇥詞性⇥中文⇥英文`，回 `{created, skipped, errors[]}`
- `POST /api/entries/:id/audio`（≤1MB、mime 白名單）、`DELETE /api/audio/:id`
- `POST /api/books`、`PATCH /api/books/:id`、`POST /api/books/:id/units`、`PATCH /api/units/:id`
- `POST /api/units/:id/publish`、`POST /api/units/:id/unpublish`

**管理（admin 以上）**
- `GET/PATCH/DELETE /api/admin/users`、`POST /api/admin/grants`、`DELETE /api/admin/grants/:id`
- `GET /api/admin/audit-logs`（篩選 + 分頁）
- `GET /api/admin/health` → `backend`（json/supabase）、`db_key_type`、`schema_ready`

降級原則（沿用 competition-manager）：Supabase 模式未執行 migration 時，公開讀取端點回 200 + `schema_ready:false`；
寫入端點回 503 並指出該執行哪個 migration 檔，**不要整站壞掉**。


**Apple 設計原則的具體落地**（美觀不是重點，但照規範做成本一樣）：

- 系統字體堆疊 `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang TC", system-ui`；
  大標題 `letter-spacing: -0.02em`、行高 1.05；正文行高 1.6（原則 15）。
- 頂部導覽列半透明 + `backdrop-filter: blur(20px) saturate(180%)`，內容在下方滾動（原則 12）。
- **按下即回饋**：`button:active { transform: scale(0.97) }`、`transition: transform 100ms ease-out`（原則 1）；
  生字卡 hover 抬起、🔊 播放中顯示波形（原則 13：回饋只放在值得的地方）。
- 動效只用 `transform` / `opacity`；`prefers-reduced-motion: reduce` 全部降為淡入（原則 14）。
- 顏色一律走 CSS 變數（淺色 + 深色兩份、跟隨系統）；**不得有任何行內 style / 行內 onclick**
  （CSP `script-src 'self'`、`style-src 'self'`；動態按鈕一律 `data-*` + 委派監聽，並加守門測試）。
- 觸控目標 ≥44px、手機不橫向溢出、輸入框字級 16px（防 iOS 聚焦放大）。

## 九、安全基線

1. JWT 不放 password；role 不當授權依據（每次查資料庫）。
2. `JWT_SECRET` 只從環境變數取，production 缺少就 fail-fast；不寫進 Git。
3. 憑證在 HttpOnly cookie（`SameSite=Strict`、production 加 `Secure`）；前端不存 token。
4. CSRF：帶 cookie 的寫入請求檢查 Origin/Referer，**只比主機名、不比 scheme**（Vercel 反代下 `req.protocol` 是 http）。
5. 登入鎖定：單 IP 10 次/15 分鐘；帳號需來自 ≥2 個 IP 才鎖。
6. 上傳：mime 白名單（mpeg / mp4 / webm / wav / ogg）、單筆 ≤1MB、前端先壓縮（Vercel body 上限約 4.5MB）。
7. CSP 嚴格 + 樣式與腳本全部外部化；用 `securitypolicyviolation` 監聽驗證，不靠肉眼。
8. 公開寫入端點節流 + 欄位長度上限。
9. 錯誤日誌：自動化檢查流量帶自簽標記，不污染正式站日誌。
10. 稽核：新增／編輯／刪除／發佈／核准／登入登出全部寫 `dict_audit_logs`。

## 十一、風險與對策

| 風險 | 說明 | 對策 |
|---|---|---|
| TTS 聲音不一致 | 不同裝置／瀏覽器聲音不同；離線無 TTS | 介面明說；老師錄音可覆蓋；v0.3.0 可做伺服器端預生成 |
| iOS Safari TTS | 必須在使用者手勢中播放 | 點 🔊 即手勢；不支援時停用並提示 |
| JSON store 無並發保護 | Demo 單機單實例可行，多實例會互相覆蓋 | README 明說；上線前切 Supabase |
| Supabase 額度 | 免費方案每組織上限 2 個活躍專案（比賽管理系統 + old_trees 已滿） | 上線階段：新組織／暫停一個／升 Pro，或表名 `dict_` 前綴共存 |
| 音檔累積 | 每字一段錄音會長大 | 單筆 1MB、30 秒上限；日後改存物件儲存 |
| 資料量 | 一本書 12 單元 × 20 字 = 240 筆 | 批次貼上匯入；v0.2.0 加 CSV 匯入與單元複製 |
