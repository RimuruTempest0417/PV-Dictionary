# 發版流程（每個版本照這個跑）

> 使用者 2026-10-10 指定：**每次更新都要檢查有沒有錯誤記錄需要處理**。
> 所以「發版前檢查」做成一個指令 `npm run release:check`，不用靠記得。

## 一個指令：`npm run release:check`

它會依序做這些事，最後回非 0 就代表「還不能發」：

1. **本機**：`check:syntax`（所有 JS 語法＋ server 模組載入）、`check:schema --offline`（程式要用的欄位 vs 遷移檔）、`npm test`。
2. **錯誤記錄檢查**（使用者指定）：直接讀線上資料庫的 `dict_error_logs`，
   把**還沒標記處理**的錯誤依 `code → path` 分組列出（新的排前面）。
   - **最近 24 小時內**出現的未處理錯誤 → **擋住發版**（要嘛修、要嘛標成已處理）。
   - 例外：`ASSET_LOAD`／`CSP_VIOLATION`（使用者端瀏覽器或擴充功能造成的）只提醒，不擋。
   - 怎麼處理：開後台「🐞 錯誤紀錄」看細節（或 `npm run triage` 分組），修好後標成「已處理」再跑一次。
3. **線上**：`uptime`（版本／健康／容量／金鑰效期）、`live-verify --ephemeral-teacher`（真的寫入→讀回→清掉）、
   正式站訪客視角真瀏覽器檢查。

其他選項：`--fast`（只跑本機＋錯誤記錄）、`--errors`（只看錯誤記錄）。

## 發版步驟（每一版都一樣）

```bash
npm run release:check               # 上面那一串（全綠才往下）
npm run check:browser               # 本機真 Chrome 四支（329 項；改到畫面一定要跑）
# 1) 版本號同步：package.json、public/index.html（title／?v=／頁尾）、README 開頭
# 2) 寫 docs/release/release-vX.Y.Z.md（這一版為什麼做、怎麼驗、實測數字）
git add -A && git commit -m "vX.Y.Z：一句話"
git tag -a vX.Y.Z -m "..." && git push origin main && git push origin vX.Y.Z
# 3) 等 Vercel 部署：curl -s https://gary-dictionary.vercel.app/api/version（四個網址都要跟上）
# 4) 部署後再跑一次線上驗收（模擬器會抓到「本機測不出來」的問題）：
node scripts/live-verify.js --ephemeral-teacher && npm run check:live-browser && npm run uptime
# 5) GitHub Release + 獨立讀回
node scripts/gh-release.js vX.Y.Z docs/release/release-vX.Y.Z.md "標題後半"
```

## 為什麼一定要「部署後再驗一次」

v0.11.0 就是這樣被抓到的：本機（JSON 模式）與單元測試全綠，但正式站的單元頁整條 500
（視窗化資料層的音檔標記漏了沒有錄音的生字）。**凡是動到資料層視窗或路由互動的改動，
只有 `live-verify`（真的寫入→讀回→清掉）會現形。** 詳見 `docs/release/release-v0.11.1.md`。

## 每天／每季自動跑的東西（不用手動）

| 排程 | 指令 | 做什麼 | 紀錄 |
|---|---|---|---|
| 每天 03:30 | `scripts/backup.js` | 資料庫備份 → 私有 repo（保留 30 份） | `logs/backup.log` |
| 每天 08:30 | `scripts/monitor.js` | 健康檢查，失敗發 macOS 通知 | `logs/uptime.log` |
| 每季首日 08:40 | `scripts/quarterly-review.js --notify` | 規模／用量／待辦＋提醒看 Neon 條款 | `logs/quarterly.log`、`logs/quarterly-review.json` |

手工工具：`npm run quarterly`（隨時看現況）、`npm run quarterly -- --record`（做完人工檢查後記錄）、
`npm run usage`（各表筆數）、`npm run triage`（錯誤日誌分組）、`npm run cleanup:logs`（保留期清理）。
