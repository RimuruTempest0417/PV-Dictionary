# 金鑰輪替（A-9）

什麼時候要做：**懷疑外流**（貼到對話、截圖、共用電腦、離職同仁）、**換手**（換人管理），
或是定期（建議每學年一次）。輪替會讓**所有已登入的人被登出**（`JWT_SECRET` 一換，舊權杖全部失效），
所以安排在放學後或假日。

## 兩個機密

| 名稱 | 放在哪 | 用途 | 外流的後果 |
|---|---|---|---|
| `JWT_SECRET` | Vercel 環境變數（sensitive） | 簽／驗登入權杖 | 任何人都能自己簽一張管理員權杖 |
| `SUPABASE_SERVICE_ROLE_KEY` | Vercel 環境變數（sensitive） | 後端用資料庫（繞過 RLS） | 整個資料庫被讀寫（含帳號） |
| `VERCEL_TOKEN` | 只在 `.env`（本機，不進 Vercel） | 部署與推環境變數 | 別人能改你的網站與環境變數 |

> 本機的 `.env` 與 `data/` 都不在版控裡（`.gitignore`）。**不要把任何金鑰貼進對話、文件或截圖**；
> 要驗證就在 shell 裡直接從 `.env` 讀，例如 `PW=$(grep '^SEED_MANAGER_PASSWORD=' .env | cut -d= -f2)`，
> 值只留在那個行程裡，不會出現在輸出。

## 步驟（以 `JWT_SECRET` 為例）

1. **產新值**（不要用密碼、不要用重複的字串）：
   ```bash
   node -e 'console.log(require("crypto").randomBytes(48).toString("base64url"))'
   ```
2. **只在本機改 `.env`**（同一個檔案裡同時有 `JWT_SECRET` 與 `VERCEL_TOKEN` 才推得上去）。
3. **推上 Vercel 並重新部署**：
   ```bash
   node scripts/vercel-env.js --check     # 先看目前有沒有設、型別對不對（不會顯示值）
   node scripts/vercel-env.js --push --deploy
   ```
4. **讀回確認**（這一步不能省）：
   ```bash
   curl -s https://gary-dictionary-mylearning.vercel.app/api/health
   ```
   `jwt_secret_configured` 要是 `true`，`schema_ready` 要是 `true`；再看：
   ```bash
   curl -s https://gary-dictionary-mylearning.vercel.app/api/version
   ```
5. **驗證登入仍可用**：自己登入一次（舊的登入狀態會失效，這是預期的）。
6. **記錄**：在這一頁最後的紀錄表加一列（換了什麼、日期、為什麼）。

**v0.10.0 起：`SUPABASE_SERVICE_ROLE_KEY` 是自簽 JWT。** 搬到 Neon（Data API）後，它不再是 Supabase 的長字串 key，
而是**我們自己簽的 JWT**（`role=authenticated`、`aud=gary-dictionary`、有效期 **365 天**）。輪替有兩種做法，完全不同：

- **只換 token**（同一個簽章金鑰）：用 `node scripts/neon-jwt.js` 重簽一個新 token，照上面的步驟 3–5 推上 Vercel；
  舊 token 到期前仍有效（**換 token ≠ 撤銷舊 token**），零停機。
- **換簽章金鑰**（真撤銷）：`node scripts/neon-jwt.js --make-keys` 後更新 Neon Console 的 JWKS。

完整的兩種做法與演練結果見 `docs/搬家到Neon.md` 第五節。

**（舊 Supabase 時期適用）** 以下做法只在還在使用 Supabase 時有效：`SUPABASE_SERVICE_ROLE_KEY` 的步驟一樣，
但最後多一步：**舊 key 要停用**。
到 Supabase → Settings → API → `service_role` 的選單選 **Rotate**（或在 API keys 頁把舊的撤銷），
然後重跑步驟 3–5。若輪替後 `/api/health` 的 `db.ok` 是 `false`，先看它的 `lastError`，通常是舊 key 還在用。

## 輪替後一定要一起確認的三件事

1. `/api/health`：`jwt_secret_configured=true`、`schema_ready=true`、`db.ok=true`。
2. 登入後「帳號管理」打得開、稽核紀錄看得到（代表權杖與資料庫都通）。
3. 學生端（免登入）看得到書架與生字（代表公開路徑沒被擋）。
