# 備份與還原（A-2，v0.9.0）

> 目的：**資料庫要有一份放在我們自己手上的備份**（不依賴 Supabase 的免費方案）。
> 備份放**私有** GitHub repo：`RimuruTempest0417/gary-dictionary-backup`。

## 怎麼跑

```bash
cd ~/Documents/hermes/GD-English-Dictionary
npm run backup                 # 匯出 → commit → push（保留最近 30 份）
npm run backup -- --dry-run    # 只匯出到暫存資料夾，不 push
npm run backup -- --keep=14    # 只保留最近 14 份
```

跑完會印出每張表的筆數與 push 結果，例如：

```
→ 匯出 hckozqluooeobvyltcyf.supabase.co 的資料（只讀，不動正式站）
  books：1 筆（1226695 bytes）
  …
  schema/：6 個 SQL｜manifest：8 個檔案｜總計 93 筆
✔ 備份已推上 https://github.com/RimuruTempest0417/gary-dictionary-backup/tree/main/backups/2026-10-10
（暫存資料夾已刪除，你的電腦不留檔案）
```

## 備份內容

| 項目 | 說明 |
|---|---|
| `books.jsonl`／`units.jsonl`／`entries.jsonl`／`audio.jsonl`／`users.jsonl`／`grants.jsonl`／`audit_logs.jsonl`／`error_logs.jsonl` | 每張表一個檔，一行一筆（含 id，還原時原樣寫回）。音檔與封面是 base64，就在 `.jsonl` 裡 |
| `manifest.json` | 建立時間、來源網域、應用版本、每張表筆數、每個檔案的 **sha256**、資料庫大小 |
| `schema/*.sql` | 重建資料庫用的 DDL（Supabase 版 ＋ Neon 版） |
| `README.md` | 這一頁的摘要（放在備份 repo 裡，方便日後自己看懂） |

存放位置：`backups/YYYY-MM-DD/`（同一天重跑＝覆蓋那一天）。**只保留最近 30 份**，更舊的自動刪除。

## 設計上的三個保證

1. **不碰正式站的資料**：整份流程只有 `GET` 與兩個唯讀 RPC，不會刪改任何一列。
2. **不留下檔案在使用者的電腦**：全程在系統暫存資料夾（`$TMPDIR`）完成，跑完（含失敗）一定刪除；
   不會有任何檔案跑到 `~/Downloads` 或專案資料夾。
3. **憑證不經程式**：git 走 macOS keychain（跟專案 push 用的同一組憑證），程式本身不碰 token；
   備份檔裡也**不含**任何金鑰（`JWT_SECRET`、service key、Neon 私鑰都不在裡面）。

> ⚠ **這個 repo 必須是私有**：`users.jsonl` 內含帳號的密碼雜湊與 2FA 密鑰（分別是 `password_hash`、
> `totp_secret`／`backup_codes`）。外流等於帳號被接管，且 2FA 也失效。

## 還原

```bash
git clone https://github.com/RimuruTempest0417/gary-dictionary-backup.git /tmp/pv-backup
cd ~/Documents/hermes/GD-English-Dictionary

# 1) 先檢查（驗 sha256、列筆數，不會寫任何資料）
node scripts/restore.js --from=/tmp/pv-backup/backups/2026-10-10

# 2) 確認 .env 的 SUPABASE_URL 指向正確目標後，才真的還原（先清空目標再寫回）
node scripts/restore.js --from=/tmp/pv-backup/backups/2026-10-10 --confirm

# 3) 只想補寫入、不清空
node scripts/restore.js --from=… --confirm --no-wipe
```

還原後一定要跑：

```bash
npm run check:schema:live
node scripts/live-verify.js --no-auth --ephemeral-teacher
```

**還原到 Neon 也可以**：把 `.env` 的 `SUPABASE_URL` 指到 Neon 的 Data API 端點、
`SUPABASE_SERVICE_ROLE_KEY` 換成 `node scripts/neon-jwt.js --quiet --aud="gary-dictionary"` 簽出來的 token，
其他步驟一樣（同一份備份格式兩邊通用）。

## 什麼情況會用到

- 誤刪資料（例如不小心刪了整個年級）→ 從最近的備份挑一天還原。
- Supabase 免費方案出事（暫停、額度、政策變更）→ 有備份就能搬到 Neon 重開。
- 搬家到 Neon 的那一天 → 直接拿備份匯入，不用碰 Supabase 的資料庫直連。

## 自動排程（macOS launchd，已上線）

備份已改成**每天自動跑**，用 macOS 的 `launchd`（不依賴 Hermes）：

- plist：`~/Library/LaunchAgents/com.garycheong.gary-dictionary-backup.plist`
  （Label `com.garycheong.gary-dictionary-backup`）。
- 內容：直接用 `/usr/local/bin/node` 跑 `scripts/backup.js`（匯出 → 推到私有 repo → 刪除暫存檔），
  `StartCalendarInterval` 設**每天 03:30**，並開 `RunAtLoad`（登入後先跑一次）；
  輸出逐字記在**專案內的 `logs/backup.log`**（每行都有時間戳；超過 512KB 會輪替成 `backup.log.1`，
  `.gitignore` 的 `*.log` 已經排除，不會進版控）。
  ★ **為什麼是由 node 自己寫、而不是讓 launchd 直接輸出到那裡**：launchd 在 `~/Documents` 開檔會被
  macOS TCC 擋掉，整個 job 連啟動都失敗（實測 `last exit code = 78: EX_CONFIG`、`job state = spawn failed`）。
  plist 的 `StandardOutPath` 因此退回 `~/Library/Logs/gary-dictionary-backup.launchd.log`，只當技術後備。
- ★ **TCC 權限**：plist 用 `/usr/local/bin/node` 跑，而專案在 `~/Documents` 底下，
  macOS 會擋「終端以外」的行程存取；要給這個 node **完全取硬碟存取權**
  （系統設定 → 隱私權與安全性 → 完全取硬碟存取權），否則排程會被 TCC 擋住而靜默失敗。
