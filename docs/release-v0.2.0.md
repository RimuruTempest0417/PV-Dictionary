## PV_Dictionary v0.2.0 — 書架首頁 + 封面照片 + 管理選單 + 帳號只留網站管理員

使用者這一批要求（逐字）：

> 「進去的頁面看到的不是現在這樣，而是點擊老師把書本的封面拍攝後的圖片（圖片下方有書本的名稱），
> 再進入一個目錄，然後選擇單元之後才會出現生字表，還有現在的管理頁面太長了，
> 可以做個選單點擊對應按鈕後才出現對應頁面，最後請把 manager 這個權限改名為 admin，
> 然後清除除了 web manager 以外的帳號，並把 web manager 的初始帳戶名設為 Gary⋯⋯」

### 1. 三層動線：書架 → 目錄 → 生字表

- **首頁是書架**：一本書一張卡片，**上面是封面（老師拍的照片）、下面是書本名稱**（＋年級／單元數／生字數）。
- **點封面 → 目錄**：列出這本書的所有單元（Unit 編號、標題、生字數），有「← Books」可以回書架。
- **點單元 → 生字表**：原本的生字清單（生字、IPA、詞性、中文、英文、例句、🔊），有「← Units」可以回目錄。
- 搜尋框只在生字表出現（其他畫面沒有東西可以搜）。

### 2. 書本封面（老師用手機拍）

- 管理選單 → **🖼 書本封面**：選書 → 看到目前的封面或「還沒有封面」→ 「📁 選擇圖片」上傳（或「🗑 移除封面」，要按兩次）。
- 只收 **JPEG / PNG / WebP、2MB 以內**；存進資料庫（base64）並用**自家同源端點** `GET /api/covers/:id` 提供，
  所以 CSP 不用放寬、不需要外部圖床，學生的瀏覽器直接抓同一台伺服器的圖。
- 書本清單**不會**夾帶封面 base64（否則一本書幾 MB，首頁清單會變成幾十 MB 的 JSON）。
- 沒有封面的書顯示「書名代碼」的色塊卡片，不會變成空白格子。

### 3. 管理頁面改成選單（一次只顯示一塊）

原本管理區是「全部疊在一起往下捲」，現在是橫向選單，按哪個才顯示哪一塊：

`⏳ 待審核` ｜ `➕ 新增生字` ｜ `📋 批次貼上` ｜ `🏗 新增單元` ｜ `📗 新增書本` ｜ `🖼 書本封面` ｜ `🧾 稽核紀錄` ｜ `👥 帳號管理` ｜ `🔑 授權管理`

- **沒有權限的分頁不會出現**（老師看不到帳號／授權／稽核；科代表看不到新增單元／書本／封面）。
- 沒有書本／單元時，相關分頁是**停用**的（附說明），而不是按下去才報錯。
- 待審核數量直接顯示在 `⏳` 按鈕上（例如「⏳ 待審核 (2)」）。
- 稽核紀錄改成按進去才載入（預設 25 筆，原本只有 12 筆）。

### 4. 帳號：只留網站管理員

- **現在只剩一個帳號** `Gary`（角色 `web_manager`）——其他帳號（manager / teacher / classrep）已依指示刪除，
  他們的授權也一併清掉；**你的書本、單元、生字完全沒有被動到**。
- 要建其他帳號：用 `Gary` 登入 → 管理選單 → 👥 帳號管理 → ➕ 新增帳號（老師、科代表、學生都在這裡建立）。
- 種子帳號改了：`manager` 這個名字**改名為 `admin`**；`npm run seed` 預設**只建網站管理員 `Gary`**，
  要示範帳號才加 `--with-admin`（admin）／`--with-team`（teacher、classrep）。
- 新增 `npm run seed -- --prune-accounts`：把「不是網站管理員」的帳號（連授權）清掉、把網站管理員的帳號名改成 `Gary`
  並重設密碼 —— 完全不會動教材資料。

### 測試（實跑）

| 項目 | 指令 | 結果 |
|---|---|---|
| 語法 + 模組載入 | `npm run check:syntax` | 32/32 通過 |
| 單元／API／i18n | `npm test` | **50 通過 / 0 失敗**（新增書本封面的 API 測試） |
| 真 Chrome 驗收 | `npm run check:browser` | **四支全綠**：劇本 50 ＋ 空白起步 31 ＋ 語言切換 28 ＋ 帳號管理 44 |

新增的驗收真的走完整條路：書架有封面卡片 → 點封面進目錄（此時生字表還不該出現）→ 點單元才出現生字表 →
上傳一張真的 PNG 走「選檔 → FileReader → 上傳 API → 書架立刻換成封面圖 → 同源端點抓得到 image/png」→
管理選單按「👥」只顯示帳號表（授權與稽核仍關著）→ 按「🔑」換成授權面板（帳號表收起來）。
