## 刻意不做的事

- 公開自助註冊與邀請碼：校內使用，帳號一律由管理員建立（學生免登入即可查）。
- 推播通知（Web Push／VAPID）：老師人數少、站內顯示足夠；iOS 還要「加到主畫面」才收得到。
- QR 掃碼、候補名額、成績排名：那是比賽管理系統的核心，不是字典。
- 對外 API／跨網域存取：所有請求同源，維持嚴格 CORS。
- 為了容量付費升級資料庫：目前約 12 MB / 1 GB（1.2%），先用「每單元錄音上限＋用量顯示＋70% 警告」管理。
  真的不夠時：先評估 Neon 付費或第二個免費專案，最後才考慮自架。
- **自架 Supabase on Oracle Always Free**：使用者 2026-10-10 指定留到後期。評估已完成（`docs/研究-Oracle自架評估.md`），
  結論是**現在不要做** —— 官方 2026-06 把免費額度從 4 OCPU／24 GB 砍成 **2 OCPU／12 GB** 且沒有公告、
  閒置 7 天可能被回收、維運（OS／Postgres／TLS／備份／升級）全要自己來。重啟條件寫在那份文件裡。

## 工作方式

- **每一版做完停下來等確認**，使用者說「繼續」或「好」才做下一版。
- **版本號維持 `0.x.x`**；要跳 `1.x.x` 只有使用者說了才改。
- 發版條件（全綠才發）：**`npm run release:check`**（語法＋schema＋測試＋**未處理的錯誤記錄**
  ＋線上驗收，一個指令；詳見 `docs/發版流程.md`）、`npm run check:browser`（本機真 Chrome）。
- 線上驗收一律用臨時帳號與 id 水線，結束後清乾淨並比對「筆數回到開始前」。
- **檢查可以截圖，但用完就刪**（不留在專案或使用者的電腦）；回報以純文字＋實測數字為主。
  （專案機制：`screenshot()` 預設不寫檔。）
- 機密（`JWT_SECRET`、資料庫金鑰、`VERCEL_TOKEN`、Neon 私鑰）只在 `.env → 雲端` 之間流動，**不經對話**。
- 資料庫變更一律寫進 `migrations/`；切換後端／回滾用 `node scripts/switch-backend.js`（見 `docs/搬家到Neon.md`）。
