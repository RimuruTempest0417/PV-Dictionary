## 現況

線上：**https://gary-dictionary.vercel.app**（Vercel 專案 `gary-dictionary` ＋ Supabase PostgreSQL）。

功能＝**年級 → 單元 → 生字表**（畫面上只看得到年級；生字表伺服器端分頁＋搜尋）、生字 CRUD／批次貼入／.xlsx 匯入、
老師錄音＋瀏覽器 TTS（每單元上限 60 段錄音）、待審核與批次審核、帳號與授權管理、
稽核紀錄（篩選、顏色、CSV 匯出、保留期清理）、使用統計、使用說明（依身分、中英、可列印）、
中英切換、主題（跟隨系統／淺色／深色）、字級（A−／A／A+）、鍵盤操作、學生免登入。

同一個部署的其他入口（發給學生的舊連結、舊書籤都還能用）：
`gary-dictionary-mylearning.vercel.app`、`pv-dictionary.vercel.app`、`pv-dictionary-mylearning.vercel.app`。

## 待完成

### D. 效能與維運

- **D-1b（P1）資料層視窗化：Supabase 不要整表進記憶體**（★ v0.6.1 完成：生字／音檔／稽核改成
  「按請求抓需要的切片」，存取未載入的範圍會大聲拋錯；**剩下「連一列都不搬」的優化**見下面 D-1c）
  - 為什麼：v0.6.0 已完成使用者感受到的分頁與搜尋，但 adapter 仍然把整張 `dict_entries`
    在每次 hydrate 抓進記憶體（ttl 3 秒）。生字累積到幾千、幾萬筆之後，每次快取過期都要傳一整包。
  - 怎麼做：生字相關的讀取改成請求範圍查詢（只查這一頁／這一筆）：單元詳情用 `unit_id + status + limit/offset`、
    `findEntryByHeadword` 用 `unit_id + headword_norm`、`countEntries` 用 `count=exact`、刪生字時音檔用 `entry_id` 一起刪；
    books／units／users／grants 維持 hydrate。
  - 配套：假 PostgREST（`tests/supabase.test.js`）要長出這些查詢形狀；保留 `npm run check:supabase` 的真實往返 smoke。
  - 工作量：大。

- **D-1c（P2）數字改成資料庫聚合（不需要搬任何列）**
  - 為什麼：v0.6.1 已經不再把生字整表搬進記憶體，但「每個單元有幾個生字」還是抓了
    `unit_id,status` 兩個小欄位回來自己算（一萬筆約 200KB）。
  - 怎麼做：在資料庫加一個聚合函式（例如 `dict_entry_counts(unit_ids bigint[])`）＋在
    `prefetch()` 用 `/rest/v1/rpc/dict_entry_counts` 呼叫它；**需要你自己在 Supabase SQL Editor 跑一次
    那段 DDL**（我的金鑰只能讀寫資料，不能改 schema）。
  - 工作量：小（0.5 天，但要你跑一次 SQL）。

- **D-6（P2）容量月檢與提醒**
  - 為什麼：免費方案 500MB。v0.6.0 已顯示「每單元錄音上限」與「錄音總容量」，但沒有人會記得每月去看。
  - 怎麼做：`scripts/db-usage.js` 的數字接進 `/api/health` 或 `stats`（用量百分比），`npm run uptime` 超過 70% 回非 0；
    文件寫明「到 70% 要做什麼」（清稽核、清錯誤日誌、刪沒用到的錄音）。
  - 工作量：小。

### A. 安全性

- **A-2（P0）備份與還原**（你指定「這一輪先不處理」；仍是唯一沒有退路的地方）
  - 為什麼：教材與帳號只存在 Supabase 免費方案；誤刪、誤改、服務中斷都沒有退路。
  - 怎麼做：`GET /api/admin/backup`（只給 web_manager，可選含不含稽核）＋ `scripts/backup.js`

  - 工作量：中。**需要你決定**：備份放哪裡（本機／Google Drive／兩者）、要不要每日自動。

## 刻意不做的事

- 公開自助註冊與邀請碼：校內使用，帳號一律由管理員建立（學生免登入即可查）。
- 推播通知（Web Push／VAPID）：老師人數少、站內顯示足夠；iOS 還要「加到主畫面」才收得到。
- QR 掃碼、候補名額、成績排名：那是比賽管理系統的核心。
- 對外 API／跨網域存取：所有請求同源，維持嚴格 CORS。
- 為了容量付費升級 Supabase：v0.6.0 決定維持免費方案，改用「每單元錄音上限＋用量顯示」管理。

## 工作方式

- 每一版做完停下來等你確認，你說「繼續」或「好」才做下一版。
- 發版條件（全綠才發）：`npm run check`（語法＋schema＋測試）／`npm run check:browser`（本機真 Chrome）
  ／`npm run check:live-browser`（正式站真瀏覽器）／`live-verify`／`uptime`。
- 線上驗收一律用臨時帳號與 id 水線，結束後清乾淨並比對「筆數回到開始前」。
- 檢查可以截圖，但**用完就刪**（不會留在專案或使用者的電腦）。
