## A. 安全性（對照 competition-manager 查漏補缺）

> 參考 competition-manager 的**做法與踩過的坑**，不是照搬功能。那個專案是公開報名的比賽系統，
> 本專案是校內教學字典：沒有公開註冊、沒有對外推播、沒有金流，但**有學生的帳號管理權**與**老師的教材**，
> 所以「帳號被盜」與「資料遺失」是這裡最貴的風險，優先序也照這個排。

- **A-1（P1）兩步驟驗證（TOTP）給 admin 以上**
  - 為什麼：admin／web_manager 能改所有人的帳號與教材；只有密碼一道，等於一把鑰匙開全校。
  - 怎麼做：純 Node `crypto` 實作 TOTP（RFC 6238，用官方向量驗證正確性）；登入分兩段（密碼正確回 5 分鐘的 `challenge_token`，
    換正式 cookie 前必須通過驗證碼）；**任何帶 `stage` 的權杖一律拒絕**；備援碼只存雜湊；
    上級可以重設下級的 2FA（沿用現有角色階梯）；介面在「帳號管理」加一欄「2FA 狀態」。
  - 工作量：中。**需要你決定**：要不要強制（建議：admin 以上可選、但你自己的帳號開起來）。

- **A-2（P0）備份與還原**
  - 為什麼：教材與帳號只存在 Supabase 免費方案，誤刪／誤改／服務中斷都沒有退路。
  - 怎麼做：`GET /api/admin/backup`（只給 web_manager，可選是否含稽核）＋ `scripts/backup.js`（寫到 `backups/`，gitignore，
    自動保留最近 N 份，可選上傳到你的 Google Drive）；還原一律 **upsert、永不刪除**；先 `--dry-run` 預覽筆數；
    補一份「怎麼還原」的文件（含「先備份當下快照再動」的規矩）。
  - 工作量：中。**需要你決定**：備份要放哪裡（本機／Google Drive／兩者）、要不要每日自動。

- **A-3（P1）稽核紀錄：CSV 匯出＋保留期清理**
  - 為什麼：稽核表會無限長大（免費方案有容量上限）；要交報告或追查時需要匯出。篩選與顏色已完成（本版）。
  - 怎麼做：`/api/admin/audit-logs/export`（CSV，加 BOM 讓 Excel 讀中文、開頭 `= + - @` 加單引號防公式注入）；
    `/api/admin/audit-logs/cleanup`（天數下限 30、必須 `dry_run` 先看、清理本身也留一筆稽核）。
  - 工作量：小。

- **A-4（P1）公開寫入端點的節流工具**
  - 為什麼：目前公開可寫的只有登入（已有 IP／帳號雙軌鎖定）。一旦新增任何未登入可寫的端點（例如錯誤回報），
    沒有節流就等於開放資源。
  - 怎麼做：抽一個 `allowPublicWrite(ip, bucket, limit, windowMs)` 共用函式（行程內計數即可），
    所有公開寫入端點一律「先過節流、再驗欄位長度上限」。
  - 工作量：小（先建工具，等有新端點直接用）。

- **A-5（P1）錯誤日誌與前端錯誤回報**
  - 為什麼：老師遇到白畫面或按鈕沒反應，現在你只能靠他描述。
  - 怎麼做：`error_logs` 表（migration）＋ `POST /api/logs/error`（公開、節流、body 上限 512kb、只收白名單欄位）；
    前端攔 `window.onerror`／`unhandledrejection` 上報（附頁面與版本，不附任何個資）；後台新增「🐞 錯誤日誌」分頁（web_manager），
    可標記已處理；再一支**唯讀**巡檢腳本（`npm run triage`）讀線上日誌並彙整。
  - 工作量：中。**需要你決定**：錯誤日誌要不要保存截圖（建議不要，佔容量且有個資風險）。

- **A-6（P0）靜態檔被 CDN 加上 `Access-Control-Allow-Origin: *`**
  - 為什麼：實測 `https://…/js/app.js` 回 `ACAO: *`（Vercel CDN 對靜態檔的預設值）；自家 API 是乾淨的（實測 0）。
    這會讓弱點掃描報「跨域配置錯誤」，也真的讓任何網站都能用 fetch 讀我們的 JS（內容不敏感，但不該如此）。
  - 怎麼做：`vercel.json` 的 `headers` 規則，為 `/js/(.*)`、`/css/(.*)`、`/img/(.*)`、`/favicon.ico` 明確設定
    `Access-Control-Allow-Origin: https://pv-dictionary-mylearning.vercel.app` ＋ `Cross-Origin-Resource-Policy: same-origin`。
    改完**用 curl 讀回應標頭**確認（不要只看掃描器有沒有抱怨）。
  - 工作量：小。

- **A-7（P1）收緊 CSP 與加入 Permissions-Policy**
  - 為什麼：目前 CSP 沒有 `object-src`／`worker-src`／`frame-src`，也沒有 `upgrade-insecure-requests`；
    相機與麥克風（老師錄音用得到）沒有政策限制。
  - 怎麼做：`lib/auth.js` 的 `SECURITY_HEADERS` 加
    `object-src 'none'`、`frame-src 'none'`、`worker-src 'self'`、`upgrade-insecure-requests`；
    加 `Permissions-Policy: camera=(self), microphone=(self), geolocation=(), payment=()`。
    **注意**：加了 `object-src 'none'` 之後任何 `<embed>/<object>` 都會被擋（本專案沒有用到）。
  - 工作量：小（但要在真 Chrome 上重跑一次全部檢查，確認沒有東西被擋掉）。

- **A-8（P2）密碼政策與登入通知**
  - 為什麼：現在密碼只要 6～64 字元（老師／學生帳號由管理員設定）；也沒有「有人登入你的帳號」的線索。
  - 怎麼做：把**管理員建立的老師／科代表帳號**提高到最少 10 字元並擋掉與帳號相同；
    登入成功時記錄裝置指紋（UA + IP 前兩段），與上一次不同就寫一筆稽核 `LOGIN_NEW_DEVICE`（不寄信，只留紀錄與站內提示）。
  - 工作量：小。**需要你決定**：最少 10 碼會不會太麻煩（可只要求 admin 以上）。

- **A-9（P2）金鑰輪替與資料庫審計**
  - 為什麼：`JWT_SECRET` 與 `SUPABASE_SERVICE_ROLE_KEY` 一旦外流，輪替要有人知道怎麼做。
  - 怎麼做：寫一份「金鑰輪替步驟」（`node scripts/vercel-env.js --push --deploy` 換值 → 驗 `/api/health`）；
    在 Supabase 開啟連線與慢查詢檢視；把「輪替後舊 JWT 立即失效」也一併處理（見 A-10）。
  - 工作量：小（文件為主）。

- **A-10（P2）工作階段可以主動失效**
  - 為什麼：每次請求都會重新讀取使用者（所以**停用帳號立即失效，這部分已經做對了**），
    但 JWT 有效期 12 小時且沒有黑名單 → **登出後那張權杖仍然有效**，改密碼後舊權杖也還能用到到期。
  - 怎麼做：`dict_users` 加 `token_version` 欄位；簽權杖時帶入，每次請求比對，不符就當未登入；
    改密碼／改角色／登出（可選）時 +1。
  - 工作量：中。**需要你決定**：登出要不要「所有裝置一起登出」（建議：只登出自己那一台，比較不會誤傷）。

- **A-11（P1）讀取端點的快取標頭**
  - 為什麼：公開書本／單元清單每次都要打函式與資料庫；快取標頭既省成本也抗流量。
  - 怎麼做：`GET /api/books`、`GET /api/units/:id` 回 `Cache-Control: public, max-age=15, stale-while-revalidate=60`；
    改資料時（老師存檔後）前端用 `cache: 'reload'` 重取，或加 `?v=` 破快取。
  - 工作量：小。

- **A-12（P2）依賴套件與弱點掃描進流程**
  - 為什麼：現在 `npm audit` 是乾淨的（實測 0 vulnerabilities），但沒人定期看。
  - 怎麼做：`npm run check:deps`（`npm audit --omit=dev --audit-level=high`）納入發版前的 `check`；
    每版更新依賴時順手看一次。
  - 工作量：小。

## B. 教學功能（老師與學生實際會用的）

- **B-1（P1）給老師的中文「5 分鐘上手」＋站內說明頁**
  - 為什麼：老師自己會操作，你才不用一個一個教。
  - 怎麼做：站內新增「❓ 使用說明」分頁（依身分顯示不同內容：訪客看「怎麼查生字」、老師看「怎麼加生字／錄音／審核」），
    內容寫在一個共用模組（`public/js/guide.js`）＋`tests/guide.test.js` 守「不可以寫不存在的功能」；
    另外輸出 PDF/列印版給老師。
  - 工作量：中。

- **B-2（P1）生字發音的完整性**
  - 為什麼：目前「有老師錄音就播錄音，否則用瀏覽器 TTS」。學生會遇到 TTS 唸錯／沒有聲音的裝置。
  - 怎麼做：發音來源徽章（👩‍🏫 老師錄音／🤖 語音合成）＋「整單元連續播放」＋記錄哪些生字缺錄音（老師的待辦清單）。
  - 工作量：中。

- **B-3（P1）匯入：CSV／Excel**
  - 為什麼：老師手上的生字表幾乎都是 Excel／Word；現在只能一行一行貼。
  - 怎麼做：前端解析 CSV（或請老師另存 CSV）→ 預覽對應欄位 → 送出既有批次端點；同時保留貼上模式。
  - 工作量：中。**需要你決定**：要不要支援 .xlsx（要引入解析套件，會增加前端體積）。

- **B-4（P2）單元／書本的排序與複製**
  - 為什麼：換學期時常要複製去年的單元再改；課本順序也會調整。
  - 怎麼做：單元「複製」（含生字、不含錄音）＋上下移動；書本排序調整。
  - 工作量：中。

- **B-5（P2）複習清單與列印**
  - 為什麼：老師會想印生字表給學生；`print.css` 已經有基礎。
  - 怎麼做：單元頁加「🖨 列印生字表」（可選含／不含中文解釋、含／不含例句）。
  - 工作量：小。

- **B-6（P2）待審核流程的細節**
  - 為什麼：科代表新增要老師核准；目前一筆一筆核准。
  - 怎麼做：批次核准／退回、退回原因（會顯示在科代表那一側）、待審核數量在導覽列顯示。
  - 工作量：小。

- **B-7（P2）使用統計（給你看，也給老師看）**
  - 為什麼：你會想知道哪個單元最常被查、哪些生字沒有解釋。
  - 怎麼做：`GET /api/admin/stats`（只回聚合數字）＋後台一頁「📊 概況」；定期手動產出報告。
  - 工作量：中。

## C. 帳號與權限

- **C-1（P1）「我的單元」清單**
  - 為什麼：老師登入後要能一眼看到「我可以編輯的單元」（現在要自己找回那本書那個單元）。
  - 怎麼做：`GET /api/my/units`（用既有授權表算）＋書架上方一個「✏️ 我可以編輯」篩選。
  - 工作量：小。

- **C-2（P1）前後端權限一致性守門測試**
  - 為什麼：權限規則一旦前端與後端不一致，就會出現「看得到按鈕、按下去被拒」或是「看不到但其實能做」。
  - 怎麼做：一支測試把「前端顯示規則」與「後端角色要求」逐項對照（新增角色／新增功能時必須補一列）。
  - 工作量：小（但需要盤點一次現有規則）。

- **C-3（P2）帳號自助與救援**
  - 為什麼：老師忘記密碼時，現在只有你能重設。
  - 怎麼做：admin 以上可以重設老師的密碼（已有）＋「顯示臨時密碼一次」的流程（不要用 email，校內沒有寄信服務）；
    web_manager 保留最終救援。
  - 工作量：小。

- **C-4（P2）角色說明頁**
  - 為什麼：權限有六級，老師會問「科代表能做什麼」。
  - 怎麼做：說明頁一節「角色與權限對照表」（由後端的角色標籤產生，避免各寫一份）。
  - 工作量：小。

## D. 效能與維運

- **D-1（P1）資料層第二階段：不要整表進記憶體**
  - 為什麼：v0.3.3 已經把「每個請求抓 7 張表」與 base64 大欄位處理掉；但資料量長大（幾千個生字）後，
    整表讀進記憶體仍會變成瓶頸。
  - 怎麼做：改成「只查這一頁需要的列」＋伺服器端分頁；生字表一次抓一頁（游標或 offset），搜尋走索引。
  - 工作量：大。

- **D-2（P1）併發寫入的樂觀鎖**
  - 為什麼：現在兩個人同時改同一筆是「後寫的贏」，會無聲無息蓋掉別人的修改。
  - 怎麼做：`updated_at`（已有）＋送 PATCH 時帶上讀到的版本，版本不同回 409 並提示「這筆已被別人改過，請重新載入」。
  - 工作量：中。

- **D-3（P2）影音檔的儲存方式**
  - 為什麼：錄音與封面目前是 base64 存在資料庫（已不進記憶體快取，但容量仍是資料庫的）。
  - 怎麼做：改用 Supabase Storage（要處理 CSP 的 `img-src`／`media-src` 與簽章網址），或維持現況並加強「每單元錄音數」的上限提示。
  - 工作量：中。**需要你決定**：要不要為了容量付費升級（免費方案 500MB）。

- **D-4（P1）外部監控**
  - 為什麼：網站掛掉時，現在只有使用者告訴你。
  - 怎麼做：用免費的 uptime 監控（每 5 分鐘打 `/api/health`，看 `schema_ready` 與 `db.hydrate_ok`），
    異常時發通知；再把「資料庫用量」也列入每月檢查。
  - 工作量：小。

- **D-5（P2）資料庫容量與保留政策**
  - 為什麼：免費方案有容量上限，沒有保留政策會慢慢長大。
  - 怎麼做：稽核清理（A-3）＋錯誤日誌清理（A-5）＋每月看一次用量；到 70% 就處理。
  - 工作量：小。

## E. 測試與工程品質

- **E-1（P1）路由清單快照與覆蓋率守門**
  - 為什麼：新增路由忘了加測試，或改動把某條路由藏掉，目前都不會有任何訊息。
  - 怎麼做：產生 `tests/fixtures/routes.json`（方法＋路徑＋中間件順序）並寫測試比對；
    另一支檢查「每條路由都被某個測試提到過」。重構時這是最有效的證明。
  - 工作量：中。

- **E-2（P1）版本一致性守門測試**
  - 為什麼：`package.json`、`index.html` 的標題與 `?v=`、`/api/version` 只要有一處忘了改就會不一致（已經手動踩過）。
  - 怎麼做：一支測試比對三處相等，並確認 `index.html` 的資產網址都帶 `?v=<版本>`。
  - 工作量：小。

- **E-3（P1）正式站的真瀏覽器「訪客視角」檢查**
  - 為什麼：`scripts/live-verify.js` 是 HTTP 層；「畫面有、但資料是空的」只有真的開瀏覽器才看得出來。
  - 怎麼做：用既有的 `tests/browser/lib/cdp.js` 寫一支打正式站的檢查：書架真的渲染出書、生字卡真的出現、
    沒有前端例外、手機尺寸不橫向溢出。**不再新增任何截圖檔**。
  - 工作量：中。

- **E-4（P2）自動化檢查流量與稽核隔離**
  - 為什麼：驗收腳本會在正式站留下真實紀錄（本版已經用臨時帳號與 id 水線清理，但登入仍會寫稽核）。
  - 怎麼做：檢查流量帶一個用 `JWT_SECRET` 簽的 `X-PV-Self-Test` 標頭，伺服器驗簽通過就在稽核 details 標記
    「自動化檢查」（或不出現在預設檢視）；沒帶／簽章錯一律照記。
  - 工作量：小。

## F. 使用者體驗

- **F-1（P1）真手機測試與修正**
  - 為什麼：學生主要用手機；現在只在小視窗模擬過。
  - 怎麼做：用你的 iPhone 走一遍（書架／目錄／生字表／🔊／直式橫式），把量到的問題修掉；
    已知要注意：`input[type=date]` 在 iOS 的原生寬度會撐破卡片（要用外框包住）、
    螢幕底部安全區（`env(safe-area-inset-bottom)`）、輸入框字級 ≥16px 防聚焦放大。
  - 工作量：中（取決於找到幾個問題）。

- **F-2（P2）加到主畫面（PWA）**
  - 為什麼：老師在手機上像 App 一樣開；學生也少一層瀏覽器。
  - 怎麼做：`manifest.json` ＋ 192／512／maskable 圖示 ＋ `apple-touch-icon`；Service Worker 只做「已載入過的單元離線可看」。
    **注意**：Service Worker 會快取檔案，改版時要正確更新（版本化快取），不要弄成「改了但學生看到舊版」。
  - 工作量：中。

- **F-3（P2）深色／淺色手動切換**
  - 為什麼：現在深色只跟隨系統；晚上備課的老師會想手動切。
  - 怎麼做：`data-theme` 屬性 + `localStorage` 記住偏好（三態：跟隨系統／淺色／深色）；兩份色票要同步（現有 tokens 已有深色票）。
  - 工作量：小。

- **F-4（P2）無障礙與鍵盤操作**
  - 為什麼：已有 `role`／`aria` 基礎，但沒系統驗過。
  - 怎麼做：Tab 走一遍全站（登入、三層動畫、生字卡、管理面板）、檢查 focus 可見、圖片有替代文字、
    顏色對比達 AA；把發現的問題修掉並寫成檢查清單。
  - 工作量：中。

- **F-5（P2）學生端的小功能**
  - 為什麼：學生是最大使用群，但目前只有「查生字」。
  - 怎麼做：單元內搜尋（現在只有全站搜尋）、點單字顯示例句、把生字加進「我的清單」（存在自己的瀏覽器，不需要帳號）。
  - 工作量：中。

## 對照 competition-manager 後，刻意**不做**的事（避免把別的專案的需求搬過來）

- 公開自助註冊與邀請碼：本系統是校內使用，帳號一律由管理員建立（學生免登入即可查）。
- 推播通知（Web Push／VAPID）：老師人數少、站內顯示就足夠；且 iOS 要「加到主畫面」才收得到，效益不高。
- QR 掃碼、候補名額、成績排名：那是比賽管理系統的核心，這裡沒有對應需求。
- 對外 API／跨網域存取：本專案所有請求都同源，維持嚴格 CORS（非白名單不回 `Access-Control-Allow-Origin`）。
