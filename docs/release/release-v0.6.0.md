## Gary-Dictionary v0.6.0 — 修改年級、編輯衝突保護、錄音上限、生字表分頁、正式站瀏覽器檢查

這一版四件事：**管理區可以直接修改年級**（不用刪掉重建）、**兩個人同時改同一筆不再無聲蓋掉**、
**每個單元的錄音有明確上限與用量顯示**、**生字表改成一次一頁**（幾千個生字也不會拖垮手機），
另外新增一支**打正式站的真瀏覽器檢查**（訪客視角）。網站網址也在這一版更名為 Gary-Dictionary。

### 1. 修改年級（使用者指定）

- 管理區「📗 新增年級」分頁下方**列出所有年級**，每一列有 **✏️** 可以改名（S1 → S3）。
- 為什麼需要：年級就是學生在書架上看到的識別；打錯字本來只能「刪掉重建」，但刪掉會連單元與生字一起沒了。
- 後端 `PATCH /api/books/:id` 只接受年級／排序／發佈狀態；**改成已經有的年級會回 409 `DUPLICATE_GRADE`**
  （兩本同年級的書，學生會分不出要點哪一個），空白年級回 400。
- 名稱改變後：書架、目錄標題、稽核紀錄（`BOOK_UPDATE`）同步更新；年級清單只給 `can_manage_content` 的身分看到 ✏️。

### 2. 編輯衝突保護（樂觀鎖，規劃書 D-2）

- 以前：兩個人同時改同一顆生字 → **後送出的人贏，前一個人的修改無聲消失**。
- 現在：前端送出它**讀到的那一筆的 `updated_at`**（`version`）；版本不同就回 **409 `STALE_WRITE`**，
  並附上最新版本，前端重新載入清單並顯示「這筆在你編輯的時候被別人改過了…」。
- 適用：生字（`PATCH /api/entries/:id`）、單元（`PATCH /api/units/:id`）、年級（`PATCH /api/books/:id`）。
- **沒有帶版本的一律照舊放行**（腳本、舊前端不會被擋在門外）；被擋下的請求**不會寫入任何資料**（有測試）。
- 順手修好一件事：**新增的列以前沒有 `updated_at`**（只有改過的列有）→ 現在新增時就會寫入，
  否則樂觀鎖對「剛建好的資料」完全失效。

### 3. 每單元錄音上限與用量（規劃書 D-3）

- 錄音仍然**存在資料庫**（不導入 Supabase Storage、不為了容量付費升級 —— 你指定的免費路線）。
- 每個單元上限 **60 段**（`AUDIO_MAX_PER_UNIT`）：到上限時新的生字不能再錄，回 400 `AUDIO_LIMIT_REACHED`
  並帶上 `{count, limit}` 讓畫面講清楚原因；**同一顆生字換一段新錄音不算新增**（會先刪舊的）。
- 老師看得到用量：錄音視窗顯示「這個單元已有 n／60 段錄音」；`GET /api/units/:id` 回 `audio_count`／`audio_limit`；
  📊 概況多回**錄音總容量（bytes）**，方便盯著免費方案的 500MB。

### 4. 生字表分頁與搜尋（規劃書 D-1）

- `GET /api/units/:id` 改成 **一頁一頁送**：`page`（預設 1）、`per_page`（預設 60、上限 200）、
  `q`（搜尋生字／中文解釋／英文解釋／詞性／美式音標）、`status`（`published`／`pending`／`rejected`）。
  回應多回 `total`、`page`、`per_page`、`has_more`。
- 前端：生字表先渲染第一頁，底部出現 **「⬇ 載入更多生字」** 與「已顯示 n／total」；
  **搜尋改成回伺服器**（輸入停 300ms 後送）—— 以前只過濾手上那一頁，還沒載入的字會「找不到」；
  「▶ 播放全部」會先把整個單元載完（播放是明確動作，值得那幾個請求）。
- **待審核清單改成獨立抓取**（`?status=pending&per_page=200`）：分頁之後不能再用「畫面上這一頁」當待審核來源，
  否則老師會漏掉沒載入的待審核生字。
- 實測（`node scripts/perf-entries.js 3000`，一個單元 3,000 個生字）：

  | 請求 | 回應大小 | 生字數 |
  |---|---|---|
  | 分頁（預設 60 筆） | **22.0 KB** | 60 |
  | 一頁 200 筆（上限） | 72.6 KB | 200 |
  | 搜尋（命中 1 筆） | **0.7 KB** | 1 |
  | 舊行為的對照：整份清單 | 1,131.6 KB | 3,000 |

  → 第一頁**省下 98.1%** 的傳輸量。

- **還沒做的部分（保留在規劃書）**：Supabase 端的資料層仍然把整張生字表放進記憶體快取（ttl 3 秒）。
  這一版先把「使用者會直接感受到」的分頁／搜尋做完；「資料層不要整表進記憶體」需要把生字相關的路由改成
  非同步查詢（現在是同步風格），工程較大，留在下一版（見 `docs/規劃書-待完成.md` 的 D-1 後續）。

### 5. 正式站的真瀏覽器「訪客視角」檢查（規劃書 E-3）

- 新增 `tests/browser/live-check.js`（`npm run check:live-browser`）：**真的開 Chrome 打正式站**，
  以訪客身分檢查：沒有前端例外、書架真的渲染出年級、載入骨架收起、標題是 Gary-Dictionary、
  版本標籤格式正確、書架沒有書名、進得了目錄與生字表、生字卡有內容與 🔊 按鈕、
  **iPhone 寬度（390×844）不橫向溢出**、有「跳至主要內容」連結。
- 依你指定的規則：**不寫任何截圖檔、不觸發任何下載、不登入、不改任何資料**。
