## PV_Dictionary v0.4.5 — 老師工作流：站內說明、我的單元、權限一致性

這一版是「老師自己看就會用」的一版：加了站內說明頁（中英）、登入後一眼看到自己能編輯的單元，
還把「權限」這件事從此釘死 —— 前端顯示的按鈕與後端真正允許的操作**用同一份資料**產生。

### 1. B-1 站內說明頁（中英雙語，❓ 在右上角）

任何人在右上角按 ❓ 就會打開說明，**只看得到與自己身分有關的章節**：

| 身分 | 看到的章節 |
|---|---|
| 訪客 | 怎麼查生字 |
| 學生 | 加上「怎麼聽讀音／用搜尋」 |
| 科代表／老師 | 加上「新增生字（含批次貼上）」「待審核」「錄音」「書本與單元」 |
| 管理員 | 加上「帳號與權限」「紀錄與數字（稽核／錯誤／概況）」 |
| 網站管理員 | 加上「緊急：所有帳號所有裝置一起登出」 |

- **列印版**：說明頁有「🖨 列印」，只印說明本身（`print.css` 的 `body[data-print-view="guide"]`），
  其他面板與按鈕不會印出來 —— 老師可以直接印給自己或貼在教室。
- **說明不會說謊**：`tests/guide.test.js` 守著三件事 ——
  每一節提到的介面元素都真的存在、每一節提到的能力在該身分真的擁有、每一句都有中英兩版且不是複製貼上。
  寫了不存在的功能，測試會紅燈（說明文件最傷的就是「按了找不到」）。
- 內容只放「怎麼做」，**不放任何截圖**（使用者指定）。

### 2. C-1 「我的單元」（登入後在書架上方）

老師／科代表登入後，書架上方會出現「✏️ 我可以編輯的單元」：每一項寫出**書名 + Unit N + 生字數 + 待審核數**，
點一下就直接跳到那個單元，不用再自己翻書找。

- 後端：`GET /api/my/units`（要登入），清單由 `lib/roles.js` 的 `canEditUnit` 決定 ——
  老師是全部、科代表預設全部但**被限縮授權時只看得到被授權的單元**（測試有斷言）。
- 學生登入也進得去，只是清單是空的（不顯示這一塊）。

### 3. C-2 前後端權限一致性守門（這一版最重要的工程改動）

以前「誰能做什麼」散在三處：後端的 `requireRole`、前端寫死的 `atLeast('teacher')`、
還有你腦袋裡的規則。三者一不一致，就會出現**看得到按鈕、按下去被拒**（或反過來）。

現在：

- **`lib/capabilities.js` 是唯一來源**（7 項能力）。`/api/auth/me` 的 `permissions` 由它產生，
  不再手寫 —— 新增功能忘了補，前端就直接拿不到那個能力。
- **前端不准再寫角色**：`public/js` 裡所有 `PDAuth.atLeast('角色')` 都改成 `PDAuth.can('能力')`，
  測試會掃描並擋下硬寫的角色。
- **`tests/fixtures/permissions.json`（32 列）**：每一列寫「能力 + 端點 + 最低角色 + 對應的介面元素」，
  測試會**拿每一列去打真實端點**（6 種身分 × 32 列 ＝ 192 次請求），
  低於門檻必須 401／403、達到門檻必須放行。
- 測試還會檢查：能力表沒有孤兒、端點沒有漏、每一列提到的 UI 元素與能力判斷真的存在。
- **這一版真的抓到一個不一致**：科代表看得到「編輯／刪除」按鈕，但後端對**已發佈**的生字要求老師權限
  （`PUBLISHED_NEEDS_TEACHER`）→ 前端現在對已發佈的生字改顯示「🔒 已發佈」，
  科代表只能改／刪自己的待審核內容（實機驗證：按下去打得開表單）。

### 4. C-4 角色與權限對照表（說明頁裡，由後端產生）

說明頁最下面有一張表：6 個角色 × 7 項能力，✓ 表示可以做。
它讀 `GET /api/roles`（公開、DB-free、可快取），**所以文件與實際規則不可能各寫一份**。
游標停在能力名稱上會顯示該能力的完整說明。

### 5. 順手：CSP 違規回報加上來源檔名

v0.4.2 的錯誤紀錄現在會連同 `source` 與 `line` 一起記，追查時不用再猜是哪一個檔案。
