## PV_Dictionary v0.4.3 — 帳號安全與工作階段

這一版把「帳號被盜」與「手機掉了」這兩件事補起來：A-1（可選兩步驟驗證）、A-8（密碼政策與新裝置登入紀錄）、
A-10（工作階段可以主動失效）、C-3（帳號救援）。另外修掉書架上的管理提示錯誤。

### 先修：書架上明明有書，提示卻說「目前還沒有任何書本」

與 v0.4.2 修的單元提示同一類錯誤：`#adminHint` 用「有沒有**選到**書本」當成「有沒有書本」。
現在書架上也分兩種：

- 真的沒有任何書本 → 警告色：「請先按『📗 新增書本』…」
- **已經有 N 本書、只是還沒點進去** → 中性色：「已經有 N 本書：點開其中一本就能看到單元。」

`backToShelf()` 也補上更新管理區狀態（與 `backToUnits()` 同一個毛病）。

### A-1 兩步驟驗證（TOTP，**可選、不強制**）

- 任何登入者都能在 🔑 彈窗自己開啟：按「開啟兩步驟驗證」→ 顯示一組密鑰（可加進 Google／Microsoft Authenticator）
  → 輸入 App 顯示的 6 位碼 → 成功後**顯示 8 組備援碼（只顯示這一次）**。
- 開啟後登入分成兩步：密碼正確只會拿到一張 **5 分鐘的中間權杖**（不發登入 cookie，
  而且**拿它呼叫任何 API 都是 401**，測試有專門驗這一條）；輸入 6 位碼或任一組備援碼才真的登入。
- 備援碼**只存雜湊**，用掉一組就從清單移除（畫面會顯示剩幾組）。
- 密鑰**加密後才存資料庫**（AES-256-GCM，金鑰由 `JWT_SECRET` 衍生）——資料庫外洩也拿不到能產生驗證碼的密鑰。
- 驗證碼只有一百萬種組合，所以第二步有節流（同一來源＋帳號 5 分鐘 10 次）。
- 實作放在 `lib/totp.js`，**照 RFC 6238 官方向量驗**（8 位碼那組），不是「看起來會動」而已。

### A-8 密碼政策與新裝置登入紀錄

- 密碼最少 **10 碼**（使用者指定），三個入口（建立帳號／管理員改密碼／自己改密碼）都擋，
  訊息會說明最少幾碼。
- 登入成功時比對上次的 **IP + 瀏覽器**：不同就單獨留一筆稽核 `LOGIN_NEW_DEVICE`，
  並在登入後提醒使用者一次（「這次是從新裝置登入——如果不是你本人，請立刻修改密碼」）。

### A-10 工作階段（使用者指定的行為）

| 動作 | 結果 |
|---|---|
| 一般登出 | **只登出自己那一台**（使用者指定），其他裝置不受影響 |
| 改自己的密碼 | 其他裝置的舊權杖立刻失效；**自己這台換一張新權杖，不用重新登入** |
| 管理員改別人的密碼／重設為臨時密碼 | 那個人的所有裝置登出 |
| **web_manager 按「登出所有裝置」** | 該帳號所有裝置一起登出（admin 不行，會回 403；兩段式確認） |

做法：`dict_users.token_version`，權杖帶著 `ver`，每次請求都比對（不符就當未登入）；
停用帳號本來就立即失效（每個請求都重讀使用者）。

### C-3 帳號救援

- 帳號管理多一欄 **「兩步驟」狀態**，以及三個新操作：
  - **產生臨時密碼**：管理員不必自己想密碼，畫面顯示一次（不寫稽核、不寫日誌），舊工作階段同時失效。
  - **重設兩步驟**：手機掉了、換手機時的救援（會留稽核 `USER_2FA_RESET`）。
  - **登出所有裝置**（僅 web_manager）。
- 權限沿用既有角色階梯：admin 可以救援下級，不能動比自己高的角色。
