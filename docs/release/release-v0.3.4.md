### 1. 稽核紀錄：篩選 ＋ 顏色分類

**篩選**（四個條件可任意組合，全部在伺服器端生效）：
動作（下拉，選項由後端 `actions` 清單產生，永遠與稽核動作同步）、帳號（輸入，350ms 去抖動）、
開始日期、結束日期；另有一顆「清除篩選」。列表上方顯示「顯示 N／共 M 筆」。

- 篩選規則集中在 `lib/audit.js` 的 `normalizeAuditFilters()` / `matchesAuditFilters()`，
  **JSON 與 Supabase 兩個資料層共用同一份**（各寫一份遲早不一致）。
- 日期用 `YYYY-MM-DD`（含當天 00:00:00.000Z～23:59:59.999Z）；**格式不對一律忽略**，
  不能讓打錯字變成「查不到任何東西」；不存在的動作回 0 筆（不會靜默變成全部）。
- 帳號篩選不分大小寫，比對 `user_id` 與顯示名稱。

**顏色分類**：每個動作歸一類，列表左側色條＋動作標籤膠囊。

| 類別 | 顏色 | 動作 |
|---|---|---|
| `create` | 綠（`--ok`） | 新增生字／匯入／新增書本・單元・帳號・授權／上傳封面・錄音 |
| `update` | 黃（`--warn`） | 修改生字・書本・單元・帳號／改自己的密碼 |
| `remove` | 紅（`--danger`） | 刪除生字・錄音・帳號／移除授權・封面 |
| `review` | 藍（`--accent`） | 核准／退回生字、發佈／下架單元 |
| `auth` | 灰 | 登入／登出 |

分類寫在 `public/js/i18n.js` 的 `AUDIT_TONES`＋字尾推斷（新動作用 `*_DELETE`、`*_APPROVE` 之類也猜得到顏色）；
**`tests/i18n.test.js` 有守門**：以後新增稽核動作若忘了歸類會直接紅燈，不會默默變成沒顏色的孤兒。

### 2. 規劃書：`docs/規劃書-待完成.md`（只放待完成的事）

- 六大類：A 安全性（12 項）、B 教學功能（7 項）、C 帳號與權限（4 項）、D 效能與維運（5 項）、
  E 測試與工程品質（4 項）、F 使用者體驗（5 項）；每項都寫「為什麼／怎麼做／工作量／需要你決定什麼」，
  最後附「建議先做這五件」與「對照 competition-manager 後刻意不做的事」。
- 安全性是拿 competition-manager 的**做法與踩過的坑**逐項對照後開出來的，不是照搬功能。
  對照後確認**本專案已經比它嚴的地方**：資料庫 RLS 全開且撤銷 anon／authenticated（那個專案是關 RLS 靠後端）、
  登入鎖定採 IP 與帳號雙軌、CSRF 只比主機名（不比 scheme，避開反代 `req.protocol` 的坑）、
  大欄位不進記憶體快取。**缺口**則列成待辦（最要緊：備份與還原、靜態檔被 CDN 加 `ACAO: *`、2FA、錯誤日誌）。

### 3. 過程中修掉的兩個「靜默失效」bug（順手加了守門測試）

- `el()` 只認 `attrs`／`dataset`，寫成 `{ 'data-tone': x }` 會被**靜默忽略**（元素在、文字對、屬性不見）。
- 同樣地 `el('option', { value: x })` 的 `value` 不會生效 → 下拉「選了卻篩不出東西」。
  兩者都只有真的在瀏覽器裡操作才會現形；已用 `attrs`／`dataset` 修正，並在 `tests/guards.test.js`
  加一條掃描，之後寫錯會直接紅燈。
