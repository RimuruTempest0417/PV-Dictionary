## PV_Dictionary v0.3.2 — 修好「上傳書本封面失敗」（以及它背後兩個更麻煩的問題）

你（使用者）上線後實際操作時回報的：

> 上傳書本封面 → `POST /api/books/1/cover` **500 Internal Server Error**，
> 畫面顯示「這次的修改沒有存進資料庫（**{message}**），請再試一次」

畫面上那個 `{message}` 是這裡唯一的線索，兩個問題都在裡面。

### 1. 真正的原因：線上資料庫少了封面的欄位

書本封面是 **v0.2.0** 加的功能，但當時**沒有人補遷移檔**。
本機 Demo 用 JSON 檔，JSON 不在乎欄位，所以：

- 本機測試全綠、真人操作也正常（你自己在本機也上傳過封面）
- 一上線 Supabase，`PATCH dict_books` 帶著不存在的 `cover_data` → PostgREST 直接拒絕 → 500

**修法**：新增 `migrations/2026-10-08-v0.3.2-cover-columns.sql`（`cover_mime`／`cover_data`／
`cover_bytes`／`cover_updated_at`／`cover_by`，idempotent），已套用到線上專案。

**更重要的是不再讓它發生**：

- `lib/schema.js`：一張表「程式會用到的欄位」清單（唯一一份）。
- `tests/schema.test.js`：比對這份清單與 `migrations/*.sql` —— **本機就擋住「加了功能忘了寫遷移檔」**。
- `scripts/schema-check.js`：同一份清單比對**線上實際 schema**（PostgREST OpenAPI），
  抓「遷移檔還沒套用到線上」。`npm run check:schema`（不需要網路）／`npm run check:schema:live`。
- `npm run check` 現在包含 `check:schema`。

### 2. 為什麼畫面只顯示 `{message}`：錯誤訊息的值沒被塞進去

後端把 `message` 寫進英文訊息字串，卻**沒有放進 JSON 的 `details`**；
前端 `errorMessage()` 用 `error.details` 做插值 → 佔位符原樣留在畫面上。

**修法（兩邊都修，才算真的修好）**：

- 後端 `DB_WRITE_FAILED` / `DB_UNAVAILABLE` 都帶 `details: { message }` → 畫面會直接顯示
  PostgreSQL 的真正原因（這次是 `column "cover_data" … does not exist`，一眼就看得出來）。
- 前端插值改成：**沒給值的佔位符整段拿掉**，連空括號 `（）` 一起收乾淨，不會再出現 `{message}`。
- 回歸測試：`tests/supabase.test.js` 用假 PostgREST 模擬「寫回失敗」，
  斷言 500 ＋ `code` ＋ `details.message`；`tests/i18n.test.js` 斷言插值後不會出現 `{}` 或空括號。

### 3. 順手修掉：id sequence 停在 1（不給 id 的 INSERT 一定撞牆）

`generated by default as identity` 只在「INSERT 不給 id」時才會動到 sequence，
但本專案的資料一律自己配 id（`max(id)+1`）→ 線上專案的 sequence 一直停在 1。
App 本身沒問題，但用 Supabase 介面補資料、或跑腳本不給 id 時就會：

```
duplicate key value violates unique constraint "dict_books_pkey"  Key (id)=(1) already exists
```

**修法**：`migrations/2026-10-08-v0.3.2-fix-id-sequences.sql`（`setval` 到各表 `max(id)`），已套用；
實測「不給 id 的 INSERT」現在正常拿到 id=2。

### 4. 線上驗收改成不需要你的密碼

`scripts/live-verify.js` 重新設計過（你已經改過 Gary 的密碼，驗收不應該因此失效）：

1. 靜態／CSP／analytics
2. **線上 schema 漂移**（欄位清單 vs 實際資料庫）
3. **資料庫直連往返**（不用登入）：插入一本帶封面的書 → `GET /api/covers/<id>` 回圖片 →
   清單顯示 `has_cover` → 刪除
4. 登入後：登入 → `/api/auth/me` → 帳號清單 → 建書 → **上傳封面** → 刪封面
   （拿不到密碼時這一段會標「略過」並提示：在 `.env` 加 `VERIFY_PASSWORD=…` 就會跑）
5. 清乾淨：只刪測試資料，並確認筆數回到開始前的數字（不再假設資料庫是空的 —— 你已經有教材了）
