## PV_Dictionary v0.4.2 — 錯誤日誌與可觀測性

這一版回答「壞掉了怎麼知道、怎麼查、資料會不會滿」：A-5、A-4、D-4、D-5、E-4，
外加修掉使用者回報的一個提示錯誤。

### 先修：目錄明明有單元，管理提示卻說「這本書還沒有單元」

`#adminHint` 只看「有沒有選到單元」（`PDState.currentUnitId`），沒看「這本書到底有沒有單元」。
使用者在目錄（還沒點進任何單元）打開管理區時，就出現錯誤的警告：「這本書還沒有單元：請按『🏗 新增單元』建立第一個單元」。
現在分成三種情況：

| 情況 | 提示 | 顏色 |
|---|---|---|
| 連書本都沒有 | 先建立書本 | 警告色 |
| 這本書真的沒有單元 | 先建立單元 | 警告色 |
| **有單元，只是還沒點進去** | 「這本書已經有 N 個單元：點開其中一個就能加入生字。」 | **中性色**（不是問題，不該嚇人） |

另外 `backToUnits()` 原本沒有更新管理區的可用狀態，回到目錄時按鈕與提示會停在「已選單元」的舊狀態 —— 一起補上。

### A-5 錯誤日誌（不存截圖）

- 新表 `dict_error_logs`（不進 hydrate 快取：它會一直長大，只在後台檢視時才讀）。
- **前端**（`public/js/errorlog.js`）：攔 `error`／`unhandledrejection`／CSP 違規／資源載入失敗，回報摘要。
  節制：同一個錯誤 30 秒內只送一次、每次載入最多 10 筆、已知無害噪音（TTS 中斷、`ResizeObserver`、
  跨來源 `Script error`）不送；401／403／404 不送（那是稽核的事），5xx 一定送。網址只送 `pathname`（不帶 query）。
- **後端**：`POST /api/logs/error`（公開＋節流）、`GET /api/admin/error-logs`（admin，可依等級／來源／狀態／日期篩選）、
  `PATCH /api/admin/error-logs/:id`（標記已處理，會留稽核 `ERROR_LOG_UPDATE`）。
  500 的錯誤處理也會寫一筆（**先寫再回覆**：serverless 回應送出後會凍結實例），`DB_UNAVAILABLE` 同理。
- **隱私**：沒有截圖欄位（使用者指定），欄位一律白名單 ＋ 長度上限，`context` 只留行號／directive 之類；
  使用者 id 不是數字就當成沒有。
- **後台**：管理選單多一頁「🐞 錯誤紀錄」，顯示等級／來源／錯誤碼／自動化檢查標記，可標記已處理與還原。

### A-4 公開寫入節流

新增 `lib/throttle.js`（記憶體計數、桶子上限 5000、會清過期的）。`/api/logs/error` 第一件事就是過節流
（同一來源每分鐘 20 次，超過回 429 + `Retry-After`）。**誠實說明**：serverless 每個實例各算一份，
所以它是「降低」而不是「完全擋死」；要完全擋死需要外部儲存，對本專案不值得。

### D-4 監控

`npm run uptime`（`scripts/uptime-check.js`）：檢查版本端點（版本要與 `package.json` 相同）、
`/api/health`（`schema_ready` + 資料庫）、公開讀取、首頁 HTML；任一項失敗就 exit 1（給排程／監控用）。
`docs/監控與錯誤追查.md` 有免費外部監控（UptimeRobot 之類）的設定步驟 —— 重點是**監控 `/api/health` 而不是首頁**，
因為資料庫掛掉時首頁還是回 200。

### D-5 用量與保留政策

- `npm run usage`：各表筆數（本機 JSON 或線上 Supabase 自動判斷），超過門檻（稽核 5000／錯誤 2000）會提醒。
- `npm run cleanup:logs`：**預設只預覽**；只刪「已處理且過期」的錯誤日誌、以及超過保留天數的稽核紀錄；
  天數下限 30 天。稽核留 365 天、錯誤日誌留 90 天。

### E-4 自動化檢查的流量不再污染你的稽核紀錄

- 驗收腳本帶 `X-PV-Self-Test: <時間戳>.<HMAC(JWT_SECRET)>`；伺服器驗簽通過且時間戳在 ±5 分鐘內才認。
- 稽核紀錄與錯誤日誌會標成 `is_self_test`，**稽核紀錄預設把它們濾掉**（`hide_self_test=0` 可以看）。
- 簽錯、過期、沒帶 → 一律當成真人操作；**絕不因為標頭就放行任何權限**。
- 實作用 `AsyncLocalStorage` 帶上下文（不是全域變數），因為 Supabase 模式的 hydrate／flush 會在 await 交錯。
